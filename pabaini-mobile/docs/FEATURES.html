Sports Hub — Phase 1: Cricket Player Profiles

✓ Implemented
🏏
In simple words: A user can optionally register as a cricket player by setting up their profile (role, batting hand, bowling style). This creates their permanent player identity in the app that everything else — teams, matches, stats — depends on.

🔃 Initialization & State Verification

  • On screen mount, the app performs a silent check against the backend: GET /sports/cricket/players/me.
  • If a player profile is returned (200 OK), the Zustand store registrations is updated to cache the profile locally.
  • If 404 Not Found is returned, the local cache is cleared.

👀 Opt-In / Just Browsing Toggle

  • Renders a full-screen welcome overlay (SportsOptIn.tsx) if the user is unregistered and has not yet completed/skipped onboarding.
  • "Just Browsing" sets seenOptIn to true in the persistent Zustand store, transitioning to the Browser Feed.
  • Unregistered users in the Browser Feed see a premium green CTA banner (SetupBanner.tsx) prompting them to "Register as a Player".

🪜 3-Step Onboarding Stack (app/sports/cricket/onboarding/)

  • Step 1 — Role Selection (role.tsx): Select specialized role: batsman, bowler, allrounder, or keeper. The "Next" button remains disabled until a selection is confirmed.
  • Step 2 — Play Style (style.tsx): Choose batting hand (Right/Left) and bowling arm/type. Applying dynamic form logic: if the user is a batsman/keeper, they can select "I don't bowl", which smoothly hides the bowling type options with LayoutAnimation.
  • Step 3 — Preview & Submit (preview.tsx): Renders a card preview. Clicking "Complete Setup" fires a POST /sports/cricket/players/me payload, updates the Zustand store, clears temporary onboarding memory, and redirects to the sports feed.

🃏 Premium Player Card (CricketPlayerCard.tsx)

  • Dark green linear gradient, radial glow highlights, cricket watermark bat emoji, user avatar, specialized role badge, style summaries, and a stats grid.

📋 Sub-Tabs Directory

  • Elegant segmented horizontal tab selector bar: Players, Teams, Matches, Leaders.
  • Players Tab: Displays the user's personal player card at the top (if registered), followed by an infinite-scroll list of other community players (GET /sports/cricket/players?page=N&limit=10).
  • Teams Tab: Fully live — see Phase 2 below.
  • Matches, Leaders: Renders challenge match fixtures and leaderboards.

🗄️ State Management & API Layer

⚡ Zustand — teamsStore.ts

  • myTeams: MyTeamResponse[] — Cached list of teams the current user is a member of (role, join date, captain info).
  • isLoadingMyTeams: boolean — Loading flag for Teams tab previews.
  • fetchMyTeams() — Calls GET /sports/cricket/teams/my and refreshes the cache. Called on tab mount and after create/join/leave actions.
  • clearMyTeams() — Clears cache on logout.

🔌 API Service — cricketTeamsApi.ts

  • All API calls use the global authenticated Axios client instance (auto-injects JWT).
  • Each function returns typed data directly from response.data.data following the backend's standard response envelope.
  • Logo upload uses multipart/form-data with a React Native file object cast.

Sports Hub — Phases 3 & 4: Cricket Matches & Scoring

✓ Implemented
🏏
In simple words: Captains can schedule matches by challenging other teams, declare their Playing XI (exactly 11 players including guests), and submit final results (simple scoring) or run live scoring ball-by-ball. Spectators can follow live scoring updates in real-time.

📅 Matches Tab & List (sports.tsx / request.tsx)

  • Match Feed Lists: Groups matches into Live Matches (pulses red with live scorecard updates), Upcoming Matches (details venue, time, and roster lineup checklist), and Completed Matches (displays the winner, trophy icon, and final summaries). Renders via MatchCard.tsx.
  • Initiate Challenge: Captains of active teams can challenge opponents via request.tsx. Fields include team/opponent dropdowns, overs (1-100), optional venue, scheduled date/time helpers, and scoring mode selector (Live vs. Simple).
  • Accept/Decline: Challenged captains view pending match requests on their Match Detail page to Accept or Decline.

ℹ&ufe0f; Match Detail (index.tsx)

  • Dynamic Scorer Actions: Renders context-specific button overlays depending on match state (Accept/Decline for challenges, Lineup Declaration, Start Match / Submit Result, Scorer Console, Watch Live, or Completed Scorecard).
  • Collapsible Scorecards: For completed matches, displays full read-only scorecard summaries and individual player stats grouped into clean, collapsible sections for each team's batting and bowling performance cards, reducing UI clutter.

🔍 Searchable Player Directory (players/index.tsx)

  • See All Players: Dedicated index view for all registered resident players, accessible via the "See All" button on the Sports tab dashboard.
  • Search & Pagination: Features a sticky search bar to filter players by name dynamically, clean skeleton loading screens, pull-to-refresh, and infinite scroll pagination (10 players per page).

👥 Declaring the Playing XI (lineup.tsx)

  • 11/11 Roster: Requires exactly 11 players to be selected from the active team squad before scoring can start.
  • Guest Players: Allows captains to manually add temporary guest players by name if they are not registered app users.
  • Batting Order: Captains assign batting slots (1 to 11) using reorder arrow controls.
  • Roster Badges: Detail pages display green/yellow "Declared" badges for both teams as client-side gates.

📝 Simple Scorecard Submission & MoM (result.tsx)

  • Winner & Scores: Form to choose winning team, final scores (e.g. 120/5 (20)), and Man of the Match.
  • Man of the Match picker: Lists both registered players and guest players (distinguished with a (Guest) label), and includes a "None / Clear" option at the top of the picker. Matches detail pages correctly display guest player MoM names.
  • Player Stats: Collapsible accordion cards for each player to input individual runs, balls, boundaries, wickets, overs, and extras.
  • 24-Hour Edit Lock: Results remain editable for 24 hours post-submission, after which the form is permanently locked and a lock padlock is shown.

🔴 Live Ball-by-Ball Scoring (start.tsx / score.tsx)

  • Toss & Openers: Initialize Match wizard to record toss winner, batting first team, opening batsmen, opening bowler, and assigned scorer.
  • Exclusive Console: Designated scorer gets exclusive write access to enter runs, wickets, and extras. Others are redirected to the public Live Viewer.
  • Automated Logic: Legal ball counters, strike rotation on runs/overs, target updates, and auto-completion.
  • Double-Tap Locks: Prevents duplicate API requests during bowler and batsman selections.
  • Wickets Modal: Input box for dismissal types (caught, bowled, run-out) and choosing the next incoming batsman. The selection list filters dynamically to exclude already-dismissed players.
  • Bowler Rotation: Blocks consecutive over bowls, prompting scorer for the next bowler at over boundaries. The previous bowler has a red Previous Bowler badge, and selecting them prompts a confirmation dialog to bypass consecutive over restrictions.
  • Match Auto-Completion: Automatically completes the match when the target is reached or all overs/wickets are exhausted, auto-dismissing active console modals to prevent errors on final-ball inputs.
  • Innings Break Wizard: Sets openers and bowling details for Innings 2.
  • One-Ball Undo: Reverts the single most recently entered delivery.

📺 Real-Time Spectator Feed (live.tsx)

  • Instant Polling: Spectators view live scoreboards, batsman summaries, bowler cards, and over trackers.
  • 5-Second Refresh: Polls the pre-computed match live record via TanStack Query every 5 seconds.
  • Diaspora Access: Operates over standard HTTP endpoints, enabling members living in UAE or UK to follow in real-time.

Guest Mode & Authentication Gating

Security

🔐 Restricted Navigation Zone

  • Guests are strictly limited to two screens: Announcements Feed (Home) and the Matches tab under Sports.
  • The top tabs for Players, Teams, and Leaders on the Sports hub are hidden entirely for guests, rendering only the Matches ScrollView.
  • Visiting gated routes directly (e.g., Roster, Create Team, Match setup, Scoring, Notifications, Resident profiles) redirects to the custom LoginRequiredGate component.

⚡ Action Intercepting Overlay

  • Interactive write triggers (such as Liking a notice, Commenting, Registering as a player, or Joining a team squad) are intercepted by the global LoginPromptModal which requests user authentication.

🔄 Auth State & Cache Clearing

  • Logouts and guest transitions flush all Zustand persistent stores (sportsStore, teamsStore, notificationsStore) and trigger a full TanStack Query client clear (queryClient.clear()) to prevent data leaking.

🛠 Bypassing Auth Headers

  • On the frontend, the Axios request interceptor checks is_guest in SecureStore and skips Firebase token acquisition.
  • On the backend, FirebaseAuthGuard and DbUserGuard are configured as optional for GET requests, enabling public notice board and matches list requests to return data successfully instead of throwing a 401 Unauthorized exception.

Global Search Screen

✓ Implemented
ℹ️
Objective: Enable users to search Pabaini's entire ecosystem (announcements, users, players, teams, matches) under a unified screen using real backend APIs. File: app/search.tsx

⚙️ Config-Driven Architecture (searchCategories.ts)

  • Unified search categories into a single extensible config array SEARCH_CATEGORIES listing tab IDs, labels, backend endpoints, empty messages, and coming soon flags.
  • Gated users category with a comingSoon: true flag, showing an Alert dialog instead of executing queries.

🔄 Debounced Input & Visual Feedback

  • Keypresses are debounced by exactly 300ms using useRef timeouts to prevent spamming search requests.
  • Active inputs receive visual focus feedback by drawing a border matching theme.colors.primary.

⚡ React Query Caching & Infinite Scroll

  • Uses useInfiniteQuery (TanStack Query v5) to load pages dynamically, tracking next-page availability via returned page meta fields (meta.page < meta.totalPages).
  • Employs onEndReachedThreshold: 0.3 to fetch next pages, showing loading spinners in the list footer, and caching results for 30 seconds (staleTime: 30_000).

📚 Parallel Queries & Recent Searches

  • All Tab: Executes parallel infinite query requests concurrently, rendering a grouped preview section (max 3 results per category) with "See all" redirects.
  • Search History: Stores the last 8 successful queries under the AsyncStorage key pabaini_recent_searches, supporting tap-to-search and clear triggers.

Safe Navigation Architecture

✓ Implemented
🔐
Problem: Rapid consecutive user taps push the same screen multiple times onto the routing stack. Going back requires clicking back multiple times, degrading UX. Additionally, tapping active items multiple times duplicates screen history.
🛠️
Solution: A centralized lock and tracker utility (src/navigation/safeNavigation.ts) using a 500ms self-healing navigation lock and duplicate pathname interception. A root PathnameTracker updates the active pathname state reactively on every navigation route shift.

⏳ Module-Level Lock Window

  • Sets a global isNavigating flag to true immediately upon routing execution.
  • Subsequent push/replace events within a 500ms threshold are automatically intercepted and ignored.
  • A self-healing setTimeout unlocks the state automatically after the delay passes.

🛡️ Duplicate Route Interception

  • Maintains a module-level globalCurrentPath reference.
  • Strips query parameters (e.g., ?focus=comments) from new Hrefs via resolvePathname to compare base paths cleanly.
  • Blocks the navigation push if the target path matches the active screen, avoiding layout duplicates.

📱 Unified Integration Areas

  • Home notice board: FAB Post button, search entry, notification bell, and AnnouncementCard touch layers.
  • Notifications: Deep-link list row redirects.
  • Global Search: Detail card redirects for Users, Players, and Teams.
  • Sports Hub & Directories: Header search buttons, player registrations, team squads list, see all lists, discover teams, and match scorecards.

16. Global App Drawer (Overlay Sidebar)

A Facebook-style overlay sidebar drawer accessible from any screen header. Built as a Modal-based component so it overlays any screen without touching the navigation stack.

🏗️ Architecture — Modal Overlay vs React Navigation Drawer

The drawer uses React Native Modal rather than React Navigation's Drawer Navigator. Key reasons:

Concern Modal Overlay ✅ RN Drawer Navigator
Expo Router compat Zero conflicts — Modal sits above all routing layers ⚠️ Requires Drawer layout file; conflicts with nested tab navigation
Reusability Drop-in on any screen with 4 lines of code Screen must live inside the Drawer Navigator subtree
Navigation stack No impact — Modal does not push to the stack Adds a navigation layer to the hierarchy
Animation control Full custom curves, simultaneous slide + fade Limited without overriding internals
Bundle size Zero new packages Adds @react-navigation/drawer + gesture-handler

Shareable Match Scorecards

✓ Implemented
ℹ️
Objective: Render, preview, and share high-resolution custom PNG scorecard images of completed matches. Entrypoint: completed match details header. Route: app/sports/cricket/matches/[id]/share-preview.tsx

📦 Third-Party Packages Used

  • react-native-view-shot: Captures component layout trees off-screen and exports them as static PNG file URIs.
  • expo-media-library: Saves exported PNG files to the user's native camera roll. Fully migrated to the new Expo SDK 56 class-based Media Library API (imported via expo-media-library/legacy for backward-compatible call signatures).
  • React Native Share: Launches the mobile OS sharing overlay to forward image URIs to external applications.

🔀 Scorecard Templates (Registry)

Templates are decoupled from the preview view and mapped in a registry for seamless extensibility:

  • Highlight Card (HighlightCard.tsx): Compact summary highlighting match score details, victory result banner, MVP Player of the Match, and top batting/bowling performers.
  • My Team Scorecard (TeamScorecardCard.tsx): Detailed batting/bowling statistics for the user's affiliated team. Falls back to Team A if user is a spectator or has no profile.
  • Full Scorecard (FullScorecardCard.tsx): Stacks Team A and Team B card layouts sequentially, divided by an innings separator.

🏗️ Core Architectural Flow

  1. Selection trigger: User selects a card template from the bottom sheet in the completed match detail screen.
  2. Immediate Feedback Overlay: A fullscreen overlay modal with a loading spinner and messages ("Preparing scorecard..." / "Creating your shareable image") pops up immediately. Concurrently, the bottom sheet retracts.
  3. Safe Navigation transit: Once the bottom sheet dismisses (350ms), the app navigates to the preview screen using the safeRouterPush click-lock utility, preventing double-triggering. The overlay then dismisses.
  4. Off-Screen Capturing: The preview screen renders a scaled visible card preview. Separately, it mounts the target template off-screen at its original 360px width inside a ViewShot wrapper utilizing absolute offsets (left: -9999). This avoids rendering glitches, content cropping, or blank cards on Android.
  5. Save/Share Actions: User hits "Save to Gallery" (triggers Media Library permissions check and writes the view-shot URI to disk) or "Share Scorecard" (calls RN's native Share sheet with the temporary image URI).
